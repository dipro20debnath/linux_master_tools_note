## 🔰 Introduction

### What is `cp`?
`cp` (copy) duplicates files and directories. It creates a **new inode** with a **new copy of data** (unlike `ln` which creates links to the same inode).

### How `cp` works internally:
1. Opens source file → reads contents
2. Creates new destination file (new inode)
3. Writes data to destination
4. Copies metadata if requested (`-p` flag)

---

## 🧰 Syntax & Options

```bash
cp [OPTIONS] SOURCE DESTINATION
cp [OPTIONS] SOURCE... DIRECTORY
```

| Flag | Long Form | Description |
|------|-----------|-------------|
| `-r` / `-R` | `--recursive` | Copy directories recursively |
| `-i` | `--interactive` | Prompt before overwrite |
| `-f` | `--force` | Force overwrite |
| `-n` | `--no-clobber` | Don't overwrite existing files |
| `-u` | `--update` | Copy only when source is newer |
| `-v` | `--verbose` | Show files being copied |
| `-p` | `--preserve` | Preserve mode, ownership, timestamps |
| `-a` | `--archive` | Archive mode (`-dR --preserve=all`) |
| `-l` | `--link` | Create hard links instead of copying |
| `-s` | `--symbolic-link` | Create symbolic links instead |
| `-b` | `--backup` | Make backup of existing files |
| `--parents` | — | Preserve source directory structure |
| `-t` | `--target-directory` | Specify target directory |

## 🟢 Basic Usage

```bash
# Copy file
$ cp file.txt file_backup.txt

# Copy to another directory
$ cp file.txt /home/dipro/Documents/

# Copy multiple files to directory
$ cp file1.txt file2.txt file3.txt /backup/

# Copy and rename
$ cp old_name.txt /path/to/new_name.txt
```

---

## 🟡 Intermediate Usage

### Copy directories recursively
```bash
$ cp -r project/ project_backup/
$ cp -rv source_dir/ /destination/   # Verbose
```

### Preserve attributes
```bash
# Preserve timestamps, permissions, ownership
$ cp -p important.conf /backup/

# Archive mode (preserves EVERYTHING — best for backups)
$ cp -a /var/www/ /backup/www/
```

### Interactive & safe copying
```bash
# Ask before overwriting
$ cp -i source.txt destination.txt

# Never overwrite
$ cp -n source.txt destination.txt

# Copy only if source is newer
$ cp -u source.txt destination.txt
```

### Backup existing files
```bash
$ cp -b file.txt /destination/
# Creates file.txt~ as backup if file.txt already exists

$ cp --backup=numbered file.txt /destination/
# Creates file.txt.~1~, file.txt.~2~, etc.
```

## 🔴 Advanced Usage

### Copy with directory structure
```bash
$ cp --parents src/components/App.js /backup/
# Creates: /backup/src/components/App.js (preserves path)
```

### Create links instead of copying
```bash
# Hard links (same inode, saves disk space)
$ cp -l large_file.iso /other_dir/

# Symbolic links
$ cp -s /path/to/original /path/to/link
```

### Mass copy with find
```bash
# Copy all .conf files preserving structure
$ find /etc -name "*.conf" -exec cp --parents {} /backup/ \;

# Copy files modified in last 24 hours
$ find . -mtime -1 -exec cp {} /recent_backup/ \;
```

### Rsync alternative for large copies
```bash
# cp with progress (using rsync instead)
$ rsync -avh --progress source/ destination/

# cp doesn't have progress bar — rsync does
```

### Script: Automated backup
```bash
#!/bin/bash
BACKUP_DIR="/backup/$(date +%Y-%m-%d)"
mkdir -p "$BACKUP_DIR"
cp -av /var/www/ "$BACKUP_DIR/www/"
cp -av /etc/nginx/ "$BACKUP_DIR/nginx/"
echo "Backup completed: $BACKUP_DIR"
```

## 🔗 Piping & Combining

```bash
# Copy files from a list
$ cat filelist.txt | xargs -I {} cp {} /backup/

# Copy and verify
$ cp file.txt /backup/ && md5sum file.txt /backup/file.txt

# Find and copy specific files
$ find . -name "*.py" | xargs -I {} cp {} /python_backup/
```

## 💡 Real World Pro Tips

1. **Use `cp -a`** for backups — preserves everything (permissions, timestamps, symlinks)
2. **Use `rsync`** instead of `cp` for large/remote copies (has progress bar, resume capability)
3. **`cp -u`** is perfect for incremental backups — only copies newer files
4. **`cp -l`** saves disk space by creating hard links
5. **Always use `-i`** on production servers to prevent accidental overwrites

### Useful aliases
```bash
alias cp='cp -i'       # Always ask before overwrite
alias cpa='cp -av'     # Archive copy with verbose
```

## ✅ Pros & Cons

| ✅ Pros | ❌ Cons |
|---------|---------|
| Simple and universal | No progress bar |
| Archive mode preserves all | Slow for large files |
| Supports hard/sym links | No resume on interrupt |
| Pattern-based with globs | Doesn't handle remote copies |

---

## 📍 Where & When to Use

| Scenario | Use `cp`? | Better Alternative |
|----------|-----------|-------------------|
| Simple file copy | ✅ Yes | — |
| Directory backup | ✅ `cp -a` | `rsync` for large |
| Remote copy | ❌ No | `scp`, `rsync` |
| Large file with progress | ❌ No | `rsync --progress` |
| Incremental backup | ✅ `cp -u` | `rsync` |
| Preserve disk space | ✅ `cp -l` (hard link) | — |

---

## ⚠️ Common Mistakes

| Mistake | Fix |
|---------|-----|
| Forgot `-r` for directories | Always use `cp -r` for dirs |
| Overwriting without asking | Use `cp -i` or `cp -n` |
| Lost permissions after copy | Use `cp -p` or `cp -a` |
| Copying symlink copies target | Use `cp -d` to preserve link |
| No progress on big files | Use `rsync --progress` |

```

```
