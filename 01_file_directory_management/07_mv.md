## 🔰 Introduction

### What is `mv`?
`mv` (move) moves files/directories to new locations or renames them. Unlike `cp`, `mv` doesn't create a new copy — it updates the directory entry.

### How `mv` works internally:
- **Same filesystem**: Just updates directory entries (rename — instant, O(1))
- **Different filesystem**: Copies data + deletes source (like cp + rm — slow)

---

## 🧰 Syntax & Options

```bash
mv [OPTIONS] SOURCE DESTINATION
mv [OPTIONS] SOURCE... DIRECTORY
```

| Flag | Long Form | Description |
|------|-----------|-------------|
| `-i` | `--interactive` | Prompt before overwrite |
| `-f` | `--force` | Force overwrite without prompt |
| `-n` | `--no-clobber` | Never overwrite existing files |
| `-u` | `--update` | Move only when source is newer |
| `-v` | `--verbose` | Show what's being done |
| `-b` | `--backup` | Make backup of existing files |
| `-t` | `--target-directory` | Specify target directory |
| `--suffix=SUF` | — | Override backup suffix (default `~`) |

## 🟢 Basic Usage

```bash
# Rename a file
$ mv old_name.txt new_name.txt

# Move file to another directory
$ mv file.txt /home/dipro/Documents/

# Move multiple files to a directory
$ mv file1.txt file2.txt file3.txt /destination/

# Rename a directory
$ mv old_project/ new_project/
```

## 🟡 Intermediate Usage

### Safe move with confirmation
```bash
$ mv -i source.txt /destination/
mv: overwrite '/destination/source.txt'? y
```

### Move only newer files
```bash
$ mv -u *.log /archive/
```

### Verbose move
```bash
$ mv -v *.txt /documents/
renamed 'file1.txt' -> '/documents/file1.txt'
renamed 'file2.txt' -> '/documents/file2.txt'
```

### Backup before overwrite
```bash
$ mv -b config.conf /etc/
# Creates /etc/config.conf~ as backup

$ mv --backup=numbered config.conf /etc/
# Creates /etc/config.conf.~1~
```

### Move directories
```bash
# Move entire directory (no -r needed unlike cp!)
$ mv project/ /backup/
```

## 🔴 Advanced Usage

### Batch rename with `rename` command
```bash
# Rename all .txt to .md
$ rename 's/.txt/.md/' *.txt

# Add prefix to all files
$ rename 's/^/backup_/' *.log

# Lowercase all filenames
$ rename 'y/A-Z/a-z/' *
```

### Batch rename with `mv` in loop
```bash
# Add date prefix to all .log files
for f in *.log; do
    mv "$f" "$(date +%Y%m%d)_$f"
done

# Change extension from .jpeg to .jpg
for f in *.jpeg; do
    mv "$f" "${f%.jpeg}.jpg"
done

# Remove spaces from filenames
for f in *\ *; do
    mv "$f" "${f// /_}"
done
```

### Atomic file replacement (safe update)
```bash
# Write new version to temp file, then mv (atomic on same filesystem)
$ cp template.conf /tmp/new_config.conf
# ... edit /tmp/new_config.conf ...
$ mv /tmp/new_config.conf /etc/app/config.conf
# This is ATOMIC — no partial writes!
```

### Move with find
```bash
# Move all .bak files to archive
$ find . -name "*.bak" -exec mv {} /archive/ \;

# Move files older than 30 days
$ find /var/log -mtime +30 -exec mv {} /archive/old_logs/ \;
```

## 🔗 Piping & Combining

```bash
# Move files from a list
$ cat files.txt | xargs -I {} mv {} /destination/

# Find and move
$ find . -name "*.tmp" | xargs -I {} mv {} /tmp/

# Move all except certain files
$ ls | grep -v "important" | xargs -I {} mv {} /other/
```

## 💡 Real World Pro Tips

1. **`mv` is instant on same filesystem** — just renames the directory entry (no data copy)
2. **Cross-filesystem mv is slow** — it copies then deletes (use `rsync` for large transfers)
3. **Atomic updates**: Use `mv` to replace config files safely (no partial writes)
4. **`rename` command** is much better than `mv` for batch renaming
5. **Always use `-i` on production servers**

### Useful aliases
```bash
alias mv='mv -i'     # Always ask before overwrite
```

### `mmv` function — move and make directory
```bash
mmv() { mkdir -p "$(dirname "$2")" && mv "$1" "$2"; }
$ mmv file.txt /new/path/that/doesnt/exist/file.txt
```

## ✅ Pros & Cons

| ✅ Pros | ❌ Cons |
|---------|---------|
| Instant rename (same FS) | Cross-FS move is slow |
| No `-r` needed for dirs | No progress bar |
| Atomic operation (same FS) | Original file gone after move |
| Backup option built-in | No undo |

---

## 📍 Where & When to Use

| Scenario | Use `mv`? | Alternative |
|----------|-----------|-------------|
| Rename file/dir | ✅ Yes | `rename` for batch |
| Move to same filesystem | ✅ Yes (instant) | — |
| Move across filesystems | ⚠️ Slow | `rsync` |
| Atomic config update | ✅ Yes | — |
| Batch rename patterns | ❌ Tedious | `rename`, loop |

---

## ⚠️ Common Mistakes

| Mistake | Fix |
|---------|-----|
| Overwriting without checking | Use `mv -i` or `mv -n` |
| Moving instead of copying | Use `cp` if you need the original |
| Slow cross-filesystem move | Use `rsync` for large transfers |
| Spaces in filenames | Quote: `mv "file name.txt" dst/` |
| Moving root dirs accidentally | Always double-check paths |

## 🧠 Cheat Sheet

```
mv src dst          → Move/rename       mv -n src dst   → No overwrite
mv f1 f2 dir/       → Move multiple     mv -u src dst   → Newer only
mv -i src dst       → Interactive       mv -b src dst   → Backup
mv -v src dst       → Verbose           mv -t dir/ f1   → Target dir

RENAME TRICKS:
mv file.{txt,md}            → Change extension
rename 's/.txt/.md/' *.txt  → Batch rename
for f in *; do mv "$f" "${f// /_}"; done  → Remove spaces
```
