## 🔰 Introduction

### What is `ps`?
`ps` (**P**rocess **S**tatus) displays a snapshot of currently running processes. It reads from the `/proc` virtual filesystem — the kernel's live process data.

### Why it matters:
- **Troubleshooting** — Find what's consuming CPU/RAM
- **Security** — Detect suspicious/unauthorized processes
- **System admin** — Monitor services, find PIDs to kill
- **Forensics** — Identify malware, backdoors, cryptominers

### Three syntax styles:
| Style | Example | Origin |
|-------|---------|--------|
| **UNIX** | `ps -ef` | Traditional Unix (dash required) |
| **BSD** | `ps aux` | BSD Unix (NO dash) |
| **GNU** | `ps --forest` | GNU long options (double dash) |

> ⚠️ `ps aux` ≠ `ps -aux` — The dash changes behavior!

## 📖 Theory — Linux Process Model

### What is a process?
A process is a **running instance of a program**. Each process has:

| Attribute | Description |
|-----------|-------------|
| **PID** | Process ID — unique number |
| **PPID** | Parent Process ID |
| **UID** | User who owns the process |
| **State** | Running, Sleeping, Stopped, Zombie |
| **Priority** | Nice value (-20 to 19) |
| **TTY** | Terminal associated with process |

### Process States:
| Code | State | Description |
|------|-------|-------------|
| `R` | Running | Currently executing or ready to run |
| `S` | Sleeping | Waiting for an event (interruptible) |
| `D` | Disk Sleep | Waiting for I/O (uninterruptible) |
| `T` | Stopped | Stopped by signal (Ctrl+Z) |
| `Z` | Zombie | Finished but parent hasn't collected exit status |
| `I` | Idle | Kernel thread, idle |

### Process hierarchy:
```
systemd (PID 1)
├── sshd
│   └── sshd (session)
│       └── bash
│           └── python3 app.py
├── nginx (master)
│   ├── nginx (worker)
│   └── nginx (worker)
└── cron
```

### `/proc` filesystem:
```bash
$ ls /proc/1234/
cmdline  cwd  environ  exe  fd  maps  status  ...
# Every process has a directory in /proc/
```

## 🧰 Syntax & Options

### BSD style (most common):
```bash
ps aux
```
| Letter | Meaning |
|--------|---------|
| `a` | Show processes from all users |
| `u` | User-oriented format (shows CPU, MEM) |
| `x` | Include processes without a terminal |

### UNIX style:
```bash
ps -ef
```
| Flag | Meaning |
|------|---------|
| `-e` | Show all processes |
| `-f` | Full format (UID, PID, PPID, CMD) |
| `-l` | Long format |
| `-u USER` | Show processes for specific user |
| `-p PID` | Show specific PID |
| `-C name` | Select by command name |

### GNU style:
| Flag | Description |
|------|-------------|
| `--forest` | Show process tree |
| `--sort=KEY` | Sort by column |
| `--no-headers` | Omit header line |

### Custom output format:
```bash
ps -eo pid,user,%cpu,%mem,cmd --sort=-%cpu
```

## 🟢 Basic Usage

```bash
# Show YOUR processes
$ ps
  PID TTY          TIME CMD
 1234 pts/0    00:00:00 bash
 5678 pts/0    00:00:00 ps

# Show ALL processes (BSD style — most popular)
$ ps aux
USER       PID %CPU %MEM    VSZ   RSS TTY  STAT START   TIME COMMAND
root         1  0.0  0.1 169360 11788 ?    Ss   10:00   0:02 /sbin/init
root       456  0.0  0.1  72300  9696 ?    Ss   10:00   0:00 /usr/sbin/sshd
dipro     1234  0.5  2.1 456780 98760 pts/0 Sl  10:05   0:15 python3 app.py

# Show ALL processes (UNIX style)
$ ps -ef
UID        PID  PPID  C STIME TTY          TIME CMD
root         1     0  0 10:00 ?        00:00:02 /sbin/init
dipro     1234  1100  0 10:05 pts/0    00:00:15 python3 app.py

# Show specific user's processes
$ ps -u dipro
$ ps -u www-data
```

### Understanding the columns:
| Column | Meaning |
|--------|---------|
| `USER` | Process owner |
| `PID` | Process ID |
| `%CPU` | CPU usage percentage |
| `%MEM` | Memory usage percentage |
| `VSZ` | Virtual memory size (KB) |
| `RSS` | Resident Set Size — actual RAM used (KB) |
| `TTY` | Terminal (`?` = no terminal) |
| `STAT` | Process state |
| `START` | Start time |
| `TIME` | Total CPU time used |
| `COMMAND` | Full command line |

## 🟡 Intermediate Usage

### Process tree (see parent-child relationships)
```bash
$ ps auxf
# Or
$ ps -ejH
# Or
$ pstree -p
systemd(1)─┬─sshd(456)───sshd(1100)───bash(1234)───python3(5678)
            ├─nginx(789)─┬─nginx(790)
            │            └─nginx(791)
            └─cron(500)
```

### Sort by CPU or Memory
```bash
# Top CPU consumers
$ ps aux --sort=-%cpu | head -10

# Top memory consumers
$ ps aux --sort=-%mem | head -10

# Sort by start time
$ ps aux --sort=start_time
```

### Custom output format
```bash
# Show only what you need
$ ps -eo pid,user,%cpu,%mem,stat,cmd --sort=-%cpu
  PID USER     %CPU %MEM STAT CMD
 5678 dipro    45.2  8.3 Rl   python3 train_model.py
 1234 mysql     2.1  5.6 Sl   /usr/sbin/mysqld
  789 root      0.5  1.2 Ss   nginx: master process

# Include PPID for parent tracking
$ ps -eo pid,ppid,user,cmd

# Show elapsed time
$ ps -eo pid,user,etime,cmd
```

### Find specific processes
```bash
# By command name
$ ps -C nginx
$ ps -C python3

# By PID
$ ps -p 1234 -o pid,user,%cpu,cmd

# By user
$ ps -u www-data -o pid,%cpu,%mem,cmd
```

## 🔴 Advanced Usage

### Security — Detect Suspicious Processes 🔒
```bash
# Find processes running as root (should you be worried?)
$ ps -eo pid,user,cmd | awk '$2 == "root"' | grep -v '\[.*\]'

# Find processes with suspicious names
$ ps aux | grep -iE 'miner|crypto|xmr|monero|kworker.*[0-9]{5}'

# Find processes listening on network ports
$ ps -eo pid,user,cmd | while read pid user cmd; do
    ls /proc/$pid/fd 2>/dev/null | while read fd; do
        readlink /proc/$pid/fd/$fd 2>/dev/null
    done
done | grep socket

# Find processes with deleted executables (malware indicator!)
$ ls -la /proc/*/exe 2>/dev/null | grep deleted

# Find hidden processes (compare ps with /proc)
$ diff <(ps -eo pid --no-headers | sort -n) <(ls /proc | grep '^[0-9]' | sort -n)

# Check for processes running from /tmp or /dev/shm (suspicious!)
$ ps aux | grep -E '/tmp/|/dev/shm/'
```

### Zombie Process Detection & Cleanup
```bash
# Find zombie processes
$ ps aux | awk '$8 ~ /Z/'
$ ps -eo pid,ppid,stat,cmd | grep -w Z

# Kill zombie's parent to clean up
$ ps -eo pid,ppid,stat | awk '$3 == "Z" {print $2}' | xargs kill -9
```

### Process Resource Analysis
```bash
# Total memory usage by user
$ ps -eo user,%mem --no-headers | awk '{arr[$1]+=$2} END {for (i in arr) printf "%s: %.1f%%\n", i, arr[i]}' | sort -t: -k2 -rn

# Count processes per user
$ ps -eo user --no-headers | sort | uniq -c | sort -rn

# Find long-running processes
$ ps -eo pid,user,etime,cmd --sort=-etime | head -20

# Find high-CPU processes (> 50%)
$ ps -eo pid,user,%cpu,cmd --sort=-%cpu | awk '$3 > 50'
```

### CTF/Pentesting — Process Enumeration 🎯
```bash
# What's running? (first thing on compromised machine)
$ ps auxf

# Find cron jobs running
$ ps -ef | grep cron

# Find services with config files
$ ps aux | grep -oP '(?<=-c |--config[= ])\S+'

# Find processes with environment variables
$ cat /proc/*/environ 2>/dev/null | tr '\0' '\n' | grep -i pass

# Check for processes running as other users (privesc clues)
$ ps -eo user,cmd | sort -u | grep -v '^\[' | grep -v "^$(whoami)"
```

## 🔗 Piping & Combining

```bash
# Find process and get PID (exclude grep itself)
$ ps aux | grep "[n]ginx"
$ ps aux | grep nginx | grep -v grep

# Count running processes
$ ps aux --no-headers | wc -l

# Kill process by name (find PID first)
$ ps aux | grep "python3 app.py" | awk '{print $2}' | xargs kill

# Monitor specific process
$ watch -n 1 'ps -p 1234 -o pid,%cpu,%mem,etime'

# Find parent process
$ ps -o ppid= -p 1234       # Get PPID of PID 1234
$ ps -p $(ps -o ppid= -p 1234) -o pid,cmd    # Show parent details
```

## 💡 Real World Pro Tips

### Tip 1: `ps aux` vs `ps -ef`
```bash
# ps aux — BSD: shows %CPU, %MEM (good for resource monitoring)
$ ps aux

# ps -ef — UNIX: shows PPID (good for process relationships)
$ ps -ef

# Both together? Custom format!
$ ps -eo pid,ppid,user,%cpu,%mem,stat,cmd
```

### Tip 2: Exclude grep from results
```bash
# ❌ Shows grep itself
$ ps aux | grep nginx
dipro  9999  grep --color=auto nginx

# ✅ Character class trick
$ ps aux | grep "[n]ginx"

# ✅ Or use pgrep
$ pgrep -a nginx
```

### Tip 3: Use `pgrep`/`pidof` for PID lookup
```bash
$ pgrep nginx           # Get PIDs
789 790 791
$ pgrep -a nginx        # Get PIDs with command
$ pidof nginx           # Get PIDs (space-separated)
```

### Tip 4: Thread view
```bash
$ ps -eLf                 # Show threads
$ ps -eo pid,nlwp,cmd     # Show thread count per process
```

## ✅ Pros & Cons

| ✅ Pros | ❌ Cons |
|---------|---------|
| Universal — on every Linux system | Snapshot only (not real-time) |
| Three syntax styles | Confusing BSD vs UNIX options |
| Custom output format | No built-in filtering by resource |
| Shows zombie/defunct processes | Output can be overwhelming |
| Reads from /proc (accurate) | Can't show short-lived processes |

## 📍 Where & When to Use

| Scenario | Command | Alternative |
|----------|---------|-------------|
| Quick process list | `ps aux` | `top` (real-time) |
| Find specific process | `ps -C name` | `pgrep name` |
| Process tree | `ps auxf` | `pstree` |
| Resource monitoring | `ps aux --sort=-%cpu` | `top`, `htop` |
| Security audit | `ps -eo pid,user,cmd` | — |
| Scripting | `ps -eo pid --no-headers` | `pgrep` |

---

## ⚠️ Common Mistakes

| Mistake | Fix |
|---------|-----|
| `ps -aux` (wrong dash usage) | Use `ps aux` (BSD) or `ps -ef` (UNIX) |
| grep showing itself in results | Use `grep "[n]ginx"` trick or `pgrep` |
| Confusing VSZ with actual RAM | Use RSS for real memory usage |
| Not checking zombie processes | `ps aux \| awk '$8~/Z/'` |
| Missing short-lived processes | Use `top` or `strace` instead |

## 🧠 Cheat Sheet

```
ps aux              → All processes (BSD — CPU/MEM)
ps -ef              → All processes (UNIX — PPID)
ps auxf             → Process tree
ps -u user          → User's processes
ps -C name          → By command name
ps -p PID           → Specific PID

CUSTOM FORMAT:
  ps -eo pid,user,%cpu,%mem,cmd --sort=-%cpu

FIND PROCESS:
  ps aux | grep "[n]ginx"    → Exclude grep
  pgrep -a nginx              → PID + command
  pidof nginx                 → PIDs only

SECURITY:
  ps aux | awk '$8~/Z/'       → Zombies
  ps aux | grep /tmp/         → Suspicious location
  ls /proc/*/exe | grep deleted → Deleted binaries

RESOURCE:
  ps aux --sort=-%cpu | head  → Top CPU
  ps aux --sort=-%mem | head  → Top memory
```
