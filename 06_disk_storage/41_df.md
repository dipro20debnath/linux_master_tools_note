## 🔰 Introduction

### What is `df`?
`df` (**D**isk **F**ree) reports the amount of disk space **used and available** on all currently mounted filesystems. It reads data from the kernel's mount table.

### Why it matters:
- **Server health** — Disk full = services crash
- **Monitoring** — Proactive capacity planning
- **Troubleshooting** — "No space left on device" errors
- **Forensics** — Identify unusual disk usage patterns

---

## 📖 Theory — Filesystem Storage

### Key concepts:
| Term | Description |
|------|-------------|
| **Filesystem** | Structure that organizes data on disk (ext4, xfs, btrfs) |
| **Mount point** | Directory where filesystem is attached (`/`, `/home`, `/var`) |
| **Block** | Smallest unit of storage (typically 4KB) |
| **Inode** | Metadata structure for each file (permissions, timestamps, pointers) |
| **Reserved space** | 5% reserved for root (prevents full-disk lockout) |

### Where `df` gets its data:
```
/proc/mounts → list of mounted filesystems
statvfs()    → system call for filesystem statistics
```

### The 5% reserved space:
```bash
# By default, ext4 reserves 5% for root
# On a 100GB disk = 5GB reserved
# This prevents non-root users from filling disk completely
# Root can still write when disk shows "100% used"

# Reduce reserved space (production servers):
$ sudo tune2fs -m 1 /dev/sda1    # Set to 1%
```

## 🧰 Syntax & Options

```bash
df [OPTIONS] [FILE/FILESYSTEM...]
```

| Flag | Description |
|------|-------------|
| `-h` | **Human-readable** (KB, MB, GB) — MOST USED |
| `-H` | SI units (1000 instead of 1024) |
| `-T` | Show **filesystem type** |
| `-i` | Show **inode** usage |
| `-a` | Show all filesystems (including pseudo) |
| `-l` | Local filesystems only |
| `-t TYPE` | Show only specific filesystem type |
| `-x TYPE` | Exclude specific filesystem type |
| `--total` | Add total row |
| `--output=FIELDS` | Custom output columns |
| `-P` | POSIX output (one line per filesystem) |

## 🟢 Basic Usage

```bash
# Human-readable (THE command you'll use most)
$ df -h
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   32G   16G  67% /
/dev/sda2       200G  145G   45G  77% /home
tmpfs            8G   256M  7.8G   4% /dev/shm
/dev/sdb1       500G  280G  195G  59% /data

# Show filesystem types
$ df -hT
Filesystem      Type  Size  Used Avail Use% Mounted on
/dev/sda1       ext4   50G   32G   16G  67% /
/dev/sda2       ext4  200G  145G   45G  77% /home
tmpfs           tmpfs  8G   256M  7.8G   4% /dev/shm

# Check specific path
$ df -h /var/log
Filesystem      Size  Used Avail Use% Mounted on
/dev/sda1        50G   32G   16G  67% /

# Check specific device
$ df -h /dev/sda1
```

## 🟡 Intermediate Usage

### Inode usage
```bash
# Check inode usage (can run out even with free space!)
$ df -hi
Filesystem     Inodes IUsed IFree IUse% Mounted on
/dev/sda1        3.2M  450K  2.8M   14% /
/dev/sda2        13M   1.2M   12M   10% /home

# ⚠️ If IUse% reaches 100%, you can't create new files
# even if disk space is available!
```

### Filter filesystem types
```bash
# Only show ext4 filesystems
$ df -hT -t ext4

# Exclude tmpfs and devtmpfs (cleaner output)
$ df -hT -x tmpfs -x devtmpfs -x squashfs

# Local filesystems only (exclude NFS/CIFS)
$ df -hl
```

### Custom output
```bash
$ df --output=source,fstype,size,used,avail,pcent,target -h
Source     Type   Size  Used Avail Use% Target
/dev/sda1  ext4   50G   32G   16G  67% /
/dev/sda2  ext4  200G  145G   45G  77% /home
```

### Total usage
```bash
$ df -h --total
...
total           750G  457G  256G  65%  -
```

## 🔴 Advanced Usage

### Disk Space Monitoring Script 🔒
```bash
#!/bin/bash
# disk_monitor.sh — Alert when disk usage exceeds threshold
THRESHOLD=85
MAILTO="admin@example.com"

df -h --output=pcent,target -x tmpfs -x devtmpfs | tail -n +2 | while read usage mount; do
    percent=${usage%%%}
    if [ "$percent" -ge "$THRESHOLD" ]; then
        echo "⚠️ WARNING: $mount is at ${percent}% usage!"
        echo "Disk $mount at ${percent}%" | mail -s "Disk Alert: $mount" "$MAILTO"
    fi
done
```

### Find what's eating disk space
```bash
# Quick: largest directories under root
$ sudo du -sh /* 2>/dev/null | sort -rh | head -10

# Drill down into specific directory
$ sudo du -sh /var/* 2>/dev/null | sort -rh | head -10

# Find large files
$ sudo find / -type f -size +100M -exec ls -lh {} + 2>/dev/null | sort -k5 -rh | head -20

# Find old log files
$ sudo find /var/log -name "*.log" -size +50M -mtime +30
```

### Inode exhaustion diagnosis
```bash
# If df -hi shows 100% inodes but df -h shows free space:
# Find directory with most files (likely cause)
$ sudo find / -xdev -printf '%h\n' | sort | uniq -c | sort -rn | head -20
# This shows directories with the most files

# Common causes: mail queues, session files, tiny cache files
```

### Forensics — Detect hidden storage 🕵️
```bash
# Compare df vs du (mismatch = deleted open files!)
$ df -h /
$ sudo du -sh /

# If df shows more used than du → deleted files held open by processes
# Find them:
$ sudo lsof +L1    # Files with 0 links (deleted but open)
# Fix: restart the process holding the file
```

## 🔗 Piping & Combining

```bash
# Get usage percentage for specific mount
$ df -h / | awk 'NR==2 {print $5}'
67%

# Alert if any filesystem > 90%
$ df -h | awk 'NR>1 && int($5) > 90 {print "ALERT:", $6, "is at", $5}'

# Monitor disk usage every 30 seconds
$ watch -n 30 'df -h -x tmpfs -x devtmpfs'

# CSV export for reporting
$ df -h --output=source,size,used,avail,pcent,target | tr -s ' ' ',' > disk_report.csv

# Sorted by usage
$ df -h | tail -n +2 | sort -k5 -rn
```

## 💡 Real World Pro Tips

### Tip 1: Clean output (exclude virtual filesystems)
```bash
$ df -hT -x tmpfs -x devtmpfs -x squashfs
# Shows only REAL disks — much cleaner!
```

### Tip 2: Check before disk full emergency
```bash
# Quick check in scripts
USAGE=$(df -h / | awk 'NR==2 {print int($5)}')
if [ "$USAGE" -gt 90 ]; then
    echo "Disk almost full! ${USAGE}%"
fi
```

### Tip 3: Free up space quickly
```bash
# Clear package cache
$ sudo apt clean                        # Debian/Ubuntu
$ sudo yum clean all                    # RHEL/CentOS

# Clear journal logs older than 3 days
$ sudo journalctl --vacuum-time=3d

# Find and delete old logs
$ sudo find /var/log -name "*.gz" -mtime +30 -delete

# Clear /tmp
$ sudo rm -rf /tmp/*
```

### Tip 4: Don't forget inodes!
```bash
# Always check both:
$ df -h     # Disk space
$ df -hi    # Inode usage
```

## ✅ Pros & Cons

| ✅ Pros | ❌ Cons |
|---------|---------|
| Instant filesystem overview | Doesn't show per-directory usage |
| Human-readable output | Includes virtual filesystems (noisy) |
| Inode tracking | Can't find WHAT's using space |
| Custom output format | Reserved space can confuse |
| Works on all Unix/Linux | Doesn't detect deleted-but-open files |

## 📍 Where & When to Use

| Scenario | Command | Alternative |
|----------|---------|-------------|
| Quick disk check | `df -h` | — |
| Check specific path | `df -h /var` | — |
| Monitor inode usage | `df -hi` | — |
| Find what uses space | — | `du -sh` |
| Server monitoring | `df` in cron script | Nagios, Zabbix |
| Clean output | `df -hT -x tmpfs` | — |

---

## ⚠️ Common Mistakes

| Mistake | Fix |
|---------|-----|
| Ignoring inode usage | Check `df -hi` too |
| Panicking at 100% (root reserved) | Root can still write (5% reserved) |
| Not filtering virtual FS | Use `-x tmpfs -x devtmpfs` |
| Only checking space, not cause | Use `du` to find large dirs |
| Deleted files still showing used | Check `lsof +L1` for open deleted files |

## 🧠 Cheat Sheet

```
df -h                    → Human-readable usage
df -hT                   → Include filesystem type
df -hi                   → Inode usage
df -h /path              → Specific path
df -h --total            → With total row
df -hT -x tmpfs          → Exclude virtual FS

MONITORING:
  df -h | awk 'int($5)>90'          → Find >90% used
  watch -n 30 'df -h'               → Live monitor

TROUBLESHOOTING:
  sudo du -sh /* | sort -rh | head  → Find large dirs
  sudo find / -size +100M           → Find large files
  sudo lsof +L1                     → Deleted open files
  df -hi                            → Inode exhaustion

CLEANUP:
  sudo apt clean                    → Package cache
  sudo journalctl --vacuum-time=3d  → Old journals
```
